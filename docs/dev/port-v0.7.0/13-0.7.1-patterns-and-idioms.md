## 1. Workspace & code organization

37 crates under `crates/` (`Cargo.toml:1-5`, `members = ["crates/*"]`). Roles:
- Foundations: `sail-common` (config, actor system `src/actor.rs`, runtime, spec, errors),
  `sail-common-datafusion` (SessionExtension, OptionLayer, TableFormatRegistry, session services),
  `sail-common-hms` (HMS proto helpers).
- Engine layers: `sail-plan` (spec→logical resolver), `sail-logical-plan` / `sail-physical-plan`
  (extension nodes/execs), `sail-logical-optimizer` / `sail-physical-optimizer`,
  `sail-sql-parser` / `sail-sql-macro` / `sail-sql-analyzer`, `sail-execution` (distributed exec),
  `sail-session` (session factories + actor SessionManager), `sail-spark-connect`,
  `sail-flight`, `sail-cli`.
- Catalogs: `sail-catalog` (manager/providers/commands) + one crate per provider
  (memory/system/glue/hms/iceberg/unity/onelake).
- Formats/datasources: `sail-iceberg`, `sail-delta-lake`, `sail-data-source` (generic formats +
  listing), `sail-function`, `sail-cache`, `sail-object-store`.
- Support: `sail-python` (`_native` cdylib), `sail-python-udf`, `sail-pyarrow`,
  `sail-celeborn` (remote shuffle), `sail-telemetry`, `sail-gold-test`, `sail-build-scripts`.

Workspace conventions:
- `[workspace.package]` version 0.7.1, edition 2024, `rust-version 1.96.0`; `[lints] workspace =
  true` on every crate; workspace clippy denies `allow_attributes`, `unwrap_used`, `expect_used`,
  `panic`, `dbg_macro`, `todo` (`Cargo.toml:17-23`). Violations need per-item
  `#[expect(clippy::unwrap_used)]` or file-level `#![allow(...)]` in tests.
- Deps centralized in `[workspace.dependencies]`; version-pinned tonic/prost/axum/datafusion/
  arrow/pyo3 block with "must match" comments (`Cargo.toml:139-207`). Feature flags minimal and
  crate-local (e.g. `sail-cli` `mimalloc`, `sail-object-store` `hdfs`).
- `clippy.toml` disallows a set of DataFusion APIs (`SessionContext::{register_table, table,
  catalog, …}`, `SessionState::{catalog_list, table_factories, …}`) so code goes through Sail's
  catalog/session instead.
- `rustfmt.toml`: `imports_granularity = "Module"`, `group_imports = "StdExternalCrate"`.

**Codegen** (always into OUT_DIR, `prettyplease`-formatted, included via `pub mod r#gen`):
- Data-source options: `data/options/*.yaml` → generated `{Name}{Read,Write}{Options,PartialOptions}`
  (`sail-build-scripts/src/data_source/options.rs`).
- Proto: per-crate `build.rs` (tonic+prost, `file_descriptor_set_path`, `pbjson` for spark
  connect) → `pub(crate) mod r#gen { tonic::include_proto!(…) }` + `FILE_DESCRIPTOR_SET` const
  (see `sail-execution/src/driver/mod.rs:13`, `sail-spark-connect/src/lib.rs:18`).
- SQL keywords (`data/keywords.txt`), system catalog YAML, function metadata yaml, telemetry
  metric registry yaml, OpenAPI REST clients (`sail-build-scripts/src/openapi/`) for Iceberg
  REST / Unity catalogs.

**License headers**: brand-new Sail files have **no** header; short "Licensed under the Apache
License, Version 2.0" headers appear only on files derived from Apache projects (most of
`sail-iceberg`/`sail-delta-lake`), full ASF headers on vendored files (e.g.
`sail-iceberg/src/spec/*`, `sail-pyarrow`). Do not add headers to new files; preserve when
carrying over vendored files.

## 2. Config system

- `AppConfig` = flat struct of sub-configs (`crates/sail-common/src/config/application.rs:23`);
  defaults from `application.yaml` (`include_str!`), a **list of `- key/type/default/description`
  items** (`loader.rs:15-40`), turned into a nested figment config by `ConfigDefinition`
  (`loader.rs:75-127`). Loading = figment over defaults + `Env::prefixed("SAIL_")` mapping
  `__`→`.` (`application.rs:74-83`). Reserved `internal: ()` swallows `SAIL_INTERNAL_*`.
- Serde idioms: `deny_unknown_fields` everywhere; kebab aliases (`#[serde(alias = "iceberg-rest")]`);
  internally-tagged enums via public enum `#[serde(into=…, from=…)]` delegating to a private
  "raw" enum carrying `type` + variants + `From` with placeholders (`MemoryPoolConfig`,
  `RetryStrategy`, `ShuffleBackend`, `application.rs:109-500`); optional-with-sentinel via
  helpers `deserialize_non_empty_string` / `deserialize_non_zero` (`loader.rs:43-73`), symmetric
  `serialize_non_empty_string` etc. in `observer.rs`; secrets via `SecretString` +
  `serialize_optional_secret`.
- Applying config to DataFusion: `ServerSessionFactory::create_session_config`
  (`crates/sail-session/src/session_factory/server.rs:104`) then `apply_execution_config`
  (:166), `apply_optimizer_config` (:181), `apply_execution_parquet_config` (:194). Session
  extensions registered there with `SessionConfig::with_extension` (see §3).

## 3. Session-extension pattern

- Trait `SessionExtension` (`name()` + Send+Sync+'static) and `SessionExtensionAccessor`
  (`crates/sail-common-datafusion/src/extension.rs:9-16`) implemented for `SessionContext`,
  `SessionState`, `&dyn Session`, `TaskContext`; retrieval idiom is uniform:
  `self.config().get_extension::<T>().ok_or_else(|| internal_datafusion_err!("session extension not found: {}", T::name()))`.
- Registered with `SessionConfig::with_extension(Arc::new(x))`. On the server factory:
  `TableFormatRegistry`, `CatalogManager`, `ActivityTracker`, `JobService`,
  `RemoteCheckpointRegistry`, `RepartitionBufferConfig`, `SystemTableService`,
  `DeltaTableCache` (`session_factory/server.rs:108-128`). Worker factory adds only
  `DeltaTableCache` + `RepartitionBufferConfig` (`session_factory/worker.rs:37-38`).
- Mutator extension point: `ServerSessionMutator` (`server.rs:39`) — `SparkSessionMutator`
  (`sail-spark-connect/src/session_manager.rs:23`, adds `PlanService` + `SparkSession`),
  `FlightSessionMutator` (`sail-flight/src/session.rs:22`).
- Extension name examples: "ActivityTracker", "JobService", "PlanService", "RepartitionBufferConfig",
  "catalog manager", "spark session".

## 4. Error handling & Result idioms

- Per-crate `XError` (thiserror) + `XResult<T>` + tiny ctors (`missing/invalid/unsupported/todo/internal/…`):
  `CommonError`, `SqlError`, `PlanError` (+ `IntoPlanResult`), `CatalogError`/`CatalogResult`,
  `ExecutionError`, `SparkError`/`SparkResult`, `SessionError`, `DataSourceError`
  (`MissingOption{key}`/`InvalidOption{key,value,cause}`), `PyUdfError`, `CacheError`.
- `#[from]` only for infra errors (DataFusion/Arrow/io/serde/prost/tonic); **sibling-crate
  errors get explicit hand-written `From` arms** so mapping is deliberate/lossy.
- Crossing into DataFusion: `impl From<MyError> for DataFusionError` wrapping
  `External(Box::new(e))` or `Plan/Internal` (e.g. `sail-data-source/src/error.rs:18-21`).
  Inside DataFusion contexts use the macros directly (`plan_err!`, `not_impl_err!`,
  `internal_err!`, `invalid_err!`, `unsupported_err!`, `plan_datafusion_err!`) — no crate-local
  macro set.
- Writer internals use `Result<_, String>`; conversion to
  `DataFusionError::Execution(...)` happens at the exec boundary.
- gRPC: `From<ExecutionError> for tonic::Status`; `SparkThrowable` maps to Spark exception class
  names + rich `ErrorDetails` (`grpc-status-details-bin`) + 2500-byte message truncation
  (`sail-spark-connect/src/error.rs:214-345`); `CommonErrorCause` is the wire classification
  (`sail-common-datafusion/src/error.rs:35`) built with `CommonErrorCause::new::<PyErrExtractor>(e)`
  (cycle-safe recursive source walk).
- Mutex/poison/channel errors flatten to `InternalError`.

## 5. Testing conventions

- In-module `#[cfg(test)] mod tests`; async via `#[tokio::test]`; per-test
  `#[expect(clippy::unwrap_used)]` or file-level `#![allow(...)]` in integration tests.
- Test-only constructors: `#[cfg(test)] fn *_for_test` or `#[cfg(test)] pub(super) mod testing`.
- Gold-data: `sail_common::tests::{TestData, test_gold_set}` (`crates/sail-common/src/tests.rs`),
  regenerate with `SAIL_UPDATE_GOLD_DATA=1 cargo test`. Parser grammar gold
  (`sail-sql-parser/tests/gold_data/syntax.json`), spark-connect conversion gold
  (`crates/sail-spark-connect/tests/gold_data/...`), and `sail-gold-test`/`spark-gold-data` bin to
  bootstrap against real Spark.
- Integration tests: only `sail-common`, `sail-sql-parser`, `sail-spark-connect` have `tests/`
  dirs (plus `wiremock` for REST-catalog style Rust tests); the heavy integration surface is
  Python.
- Python parity: `python/pysail/tests/` with root + spark `conftest.py`; `spark` fixture runs
  against Sail (pysail `SparkConnectServer`) or JVM Spark via `SPARK_REMOTE`; syrupy `yamlsnapshot`
  snapshots under `__snapshots__`; `-m integration` markers auto-deselected; container fixtures
  for iceberg-rest/MinIO/glue/hms/celeborn; pytest doctest modules with `spark` fixture.

## 6. Logging & telemetry

- Logging = `log` + `env_logger` (no `tracing` in crates); format/time from `RUST_LOG`
  (`sail-telemetry/src/telemetry.rs:162-172`). Levels: `trace!` for scan/write internals,
  `debug!` for commit context, `warn!` for recoverable issues.
- Telemetry: `init_telemetry(&TelemetryConfig, ResourceOptions { kind })` (kind e.g.
  "server"/"flight-server"/"worker"); global accessors `global_metrics()` /
  `global_system_event_reporter()`; `shutdown_telemetry()`. Metrics codegen from registry yaml.
  Execution: `trace_execution_plan(plan, TracingExecOptions { metrics, job_id, stage, attempt })`
  wraps operators with fastrace spans + metrics (`sail-telemetry/src/execution/physical_plan.rs`).
- Lifecycle events for sessions/drivers are telemetry `SystemEvent` variants (e.g.
  `SessionCreated`, `OptionCreated`), reported through the global system-event reporter.

## 7. DataFusion integration idioms

- Extension logical nodes implement `UserDefinedLogicalNodeCore` (`as_any`, `name`, private
  fields + getters, `#[derive(Educe)]` with `PartialOrd(ignore)` on schema). See
  `sail-logical-plan/src/{merge,barrier,range,show_string,repartition,...}.rs` and per-format
  write nodes (`IcebergWriteNode`, `DeltaWriteNode`, `FileWriteNode`, `CatalogCommandNode`).
- Format planner registration: `TableFormat` impls register into `TableFormatRegistry`
  (`sail-common-datafusion/src/datasource.rs:630-678`), built by
  `create_table_format_registry` (`crates/sail-session/src/formats.rs:16`). Physical
  `ExtensionPlanner`s chain by returning `Ok(None)` for foreign nodes:
  `IcebergPhysicalPlanner` (`sail-iceberg/src/physical/table_scan_planner.rs:18`),
  `DeltaPhysicalPlanner`, `ListingPhysicalPlanner`, `SystemTablePhysicalPlanner`; aggregator
  `ExtensionPhysicalPlanner` (`sail-session/src/planner.rs:165`).
- Remote execution codec: `RemoteExecutionCodec` (unit struct) implementing
  `PhysicalExtensionCodec` (`sail-execution/src/proto/codec.rs:321`); decode/encode arms per
  `ExtendedPhysicalPlanNode.NodeKind` in `crates/sail-execution/proto/sail/plan/physical.proto`
  (oneof 1–58). Non-trivial payloads travel as JSON strings or bytes
  (`try_decode_json`/`try_encode_json`). Encoding rewrites `DataSourceExec` →
  `RemoteDataSourceExec` first (`proto/encode.rs:27`). Sibling helpers
  `encode/decode_remote_physical_plan/expr/schema`.
- Object store: `DynamicObjectStoreRegistry` keyed by (scheme, authority, session fingerprint);
  `get_object_store_from_context(context, url)` helpers in `sail-iceberg/src/utils/mod.rs:101` /
  `sail-delta-lake/src/delta_log/store.rs:49`; `ObjectStoreUrl::parse(&url[..BeforePath])`
  idiom; file scans via `FileScanConfigBuilder::new(object_store_url, file_source)…` +
  `ParquetSource` (+ optional `SchemaEvolutionPhysicalExprAdapterFactoryWithMatching`); empty
  file groups padded to one empty group; repartitioning via `ExplicitRepartitionNode`/Exec
  (rewritten by the physical optimizer) or raw `RepartitionExec`.

## 8. Docs & release conventions

- `docs/`: VitePress site (`guide/concepts/reference/introduction/development/` + `public/`);
  Python API pages from Sphinx output; versioning `SAIL_VERSION`. `docs/development/` and
  `docs/dev/` hold dev-facing docs (port planning docs under `docs/dev/port-v0.7.0/`).
- Commit style (git log): conventional prefixes `feat:`/`fix:`/`docs:`/`perf:`/`refactor:`/
  `test:`/`deps:` with `(#PR)` suffixes; release prep commits `chore: prepare vX.Y.Z (#NNNN)`.
- Repo scripts/tooling: `scripts/` (spark-gold-data, spark-tests, release), `deployments/`
  (celeborn), `compose.yml` (dev services incl. MinIO/Polaris-style REST fixture for catalog
  tests), `.github/workflows`, docker images `docker/{dev,quickstart,release}` (see doc 12 §11
  for target 0.7.1 state), k8s manifests `k8s/`.
