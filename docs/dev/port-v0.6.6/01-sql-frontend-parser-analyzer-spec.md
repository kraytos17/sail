# 01 — SQL Front-End: Parser, Analyzer, Spec

> Everything in this document is added on `feat/v0.6.6` between `f090e646..b8804803`.
> It is the bottom layer of the port: without these AST/spec types nothing downstream
> compiles.

---

## 1. `crates/sail-sql-parser` — grammar additions

### 1.1 `data/keywords.txt`

- Added keyword **`CALL`** (so `CALL` can begin a statement).

### 1.2 `src/ast/statement.rs` (+28)

New statement AST variants (generated by the `#[parser]` macro; all live in the
`Statement` enum):

```rust
Statement::Call {
    call: Call,                          // the CALL keyword token
    name: ObjectName,                    // catalog.system.procedure
    arguments: ast::expression::FunctionArgumentList,  // via `compose(e, o)`
}
```

- `arguments` is a `FunctionArgumentList` (positional + named). The `compose` parser
  combinator flattens `(name => value)` named args into the same list; the analyzer
  separates them later.

```rust
Statement::ShowTblProperties {
    show: Show,
    tblproperties: Tblproperties,
    table: ObjectName,
    property_key: Option<(LeftParenthesis, StringLiteral, RightParenthesis)>,  // SHOW TBLPROPERTIES t ('key')
}

Statement::TruncateTable {
    truncate: Truncate,
    table: Table,
    name: ObjectName,
}

Statement::View {   // DESCRIBE VIEW [EXTENDED] <v>
    view: View,
    extended: Option<Extended>,
    name: ObjectName,
}
```

Note the DESCRIBE VIEW quirk that is documented in `TEST_PLAN.md`: `VIEW` comes
**before** `EXTENDED`; `DESCRIBE EXTENDED view <v>` mis-parses as table+column describe.

### 1.3 `tests/gold_data/syntax.json` (+95)

Golden parse tests for `CALL ... (arg => value)`, `SHOW TBLPROPERTIES`, `TRUNCATE
TABLE`, `DESCRIBE VIEW [EXTENDED]`, and the new ALTER TABLE forms.

## 2. `crates/sail-common::spec` — serializable plan/expression types

### 2.1 `src/spec/plan.rs` (+~80)

New command nodes and alter operations (all derive `Serialize, Deserialize`; several
also gained `PartialOrd, Ord`):

```rust
CommandNode::ShowTblProperties {
    table: ObjectName,
    property_key: Option<String>,
}

CommandNode::CallProcedure {
    name: ObjectName,
    arguments: Vec<(Option<Identifier>, Expr)>,   // (name?, value); None = positional
}
```

`AlterTableOperation` variants (the `// TODO: add all the alter table operations` marker
was replaced):

```rust
AlterTableOperation::RenameTable { new_name: ObjectName }
AlterTableOperation::AddColumns      { items: Vec<ColumnDefinition> }
AlterTableOperation::DropColumns     { names: Vec<ObjectName>, if_exists: bool }
AlterTableOperation::AlterColumnComment       { name: ObjectName, comment: Option<String> }
AlterTableOperation::AlterColumnNullability   { name: ObjectName, nullable: bool }
AlterTableOperation::AlterColumnPosition      { name: ObjectName, position: ColumnPosition }
```

New helper types:

```rust
pub struct ColumnDefinition {
    pub name: ObjectName,
    pub data_type: DataType,
    pub nullable: bool,
    pub default: Option<String>,
    pub comment: Option<String>,
}

pub enum ColumnAlterationOption {      // per-column modifiers inside ADD COLUMNS
    NotNull,
    Default(Box<Expr>),
    Comment(String),
    Position(ColumnPosition),
}

pub enum ColumnPosition { First, After(ObjectName) }
```

### 2.2 `src/spec/expression.rs`

Minor: derive `PartialOrd, Ord` on the spec expression types (needed by the new
analyzer ordering of CALL arguments and ALTER columns).

## 3. `crates/sail-sql-analyzer` — statement lowering

### 3.1 `src/statement.rs` (+784)

This is the largest analyzer change. New lowering paths:

**`Statement::Call` → `spec::CommandNode::CallProcedure`**
- Iterates the parsed `FunctionArgumentList`; each positional argument becomes
  `(None, expr)`, each named `name => value` becomes `(Some(name), expr)` (via
  `from_ast_expression`).

**`Statement::TruncateTable` → `spec::CommandNode::Delete { condition: None }`**
- TRUNCATE is rewritten to a WHERE-less DELETE. The DELETE physical path produces an
  empty snapshot (see `03-row-level-operations.md`), matching Spark/Iceberg semantics.

**`Statement::ShowTblProperties` → `spec::CommandNode::ShowTblProperties`**
- Carries `table` and `property_key` (string literal, optional).

**`Statement::Describe`**
- `DescribeItem::View` → `spec::CommandNode::DescribeTable` with the view flag so
  `DESCRIBE VIEW` doesn't run the table path.
- Column-qualified describes flow through (the resolver previously returned
  `PlanError::todo("DESCRIBE TABLE with column")`).

**ALTER TABLE mapping — `from_ast_alter_table_operation`**
- `AlterTableOperation::RenameTable { name }` → `spec::AlterTableOperation::RenameTable
  { new_name }` (single- and multi-part names; `ALTER TABLE t RENAME TO db.new_name`
  supported).
- `AlterColumn { operation: Comment(_, s) }` → `AlterColumnComment`.
- `AlterColumn { operation: SetNotNull/DropNotNull }` → `AlterColumnNullability { nullable }`.
- `AlterColumn { operation: Position(pos) }` → `AlterColumnPosition`.
- `AddColumns { items }` → `AddColumns` via `from_ast_column_alteration_list(items)`
  (builds `ColumnDefinition`s).
- `DropColumns { items, if_exists }` → `DropColumns { names, if_exists }`.
- `ReplaceColumns` and `RenamePartition` are rejected/unsupported.

Tests: `parse_alter_op` table-driven tests for every mapped operation
(`test_alter_table_rename_to`, `test_alter_table_rename_to_multipart`,
`test_alter_table_drop_columns`, `test_alter_table_drop_columns_multiple`, ...).

### 3.2 `src/parser.rs` (+31)

Wires the new statement kinds into the analyzer parse entry points (UPDATE/DELETE/MERGE
with table aliases, `SetClause` handling, CALL argument list, TRUNCATE, SHOW
TBLPROPERTIES, DESCRIBE VIEW/column).
