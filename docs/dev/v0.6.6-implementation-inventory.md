## 2. Logical-plan layer (`crates/sail-logical-plan`)

### 2.1 `src/call_procedure.rs` (new, 152 lines)

The **`CallProcedure`** enum — the resolved procedure value carried end-to-end:

```rust
pub enum CallProcedure {
    RollbackToSnapshot { table: String, snapshot_id: i64 },
    SetCurrentSnapshot { table: String, snapshot_id: Option<i64>, r#ref: Option<String> },
    ExpireSnapshots { table: String, older_than_ms: Option<i64>, retain_last: Option<i32> },
}
```

- `CallProcedure::table_name()` returns the target `ns.table` string.
- **`CallProcedureNode`** — a leaf `UserDefinedLogicalNodeCore` (`name() = "CallProcedure"`,
  no children/expressions, empty schema) carrying the procedure plus the target table
  context: `target_location`, `target_table_name: Vec<String>`,
  `target_options: Vec<OptionLayer>`, `target_lakehouse_table: Option<LakehouseExecutionContext>`.
- Accessors: `procedure()`, `target_location()`, `target_table_name()`, `target_options()`,
  `target_lakehouse_table()`. `fmt_for_explain` renders
  `CallProcedure: table=..., procedure=...`.

### 2.2 `src/load_data.rs` (new, 141 lines)

**`LoadDataNode`** — leaf extension node for `LOAD DATA INPATH '<path>' [OVERWRITE]
INTO TABLE ns.tbl`. Fields: `location: String`, `local: bool` (always `false` in v1),
`overwrite: bool`, `target_format: String`, `target_location`, `target_table_name`,
`target_options`, `target_lakehouse_table`. `name() = "LoadData"`;
`fmt_for_explain` renders `LoadData: table=..., format=..., path=..., overwrite=...`.

### 2.3 `src/merge.rs` (+163) — the row-level write core

- **`RowLevelWriteNode`** — the unified post-expansion node for DELETE/UPDATE/MERGE:
  - `command: RowLevelCommand` (`Delete | Merge | Update`),
  - `raw_target` / `raw_source` (logical scans), `raw_input_schema`,
  - `write_plan: Option<Arc<LogicalPlan>>` (expanded write plan; MERGE/UPDATE),
  - `touched_files_plan: Option<Arc<LogicalPlan>>` (yields distinct file paths to rewrite),
  - `deletion_vector_plan: Option<Arc<LogicalPlan>>` (MERGE rows deleted via DVs),
  - `condition: Option<ExprWithSource>` (DELETE/UPDATE),
  - `assignments: Option<Vec<UpdateAssignment>>` (UPDATE),
  - `merge_options: Option<MergeIntoOptions>`,
  - target metadata (format/location/table name/partition_by/options/lakehouse_table),
    `with_schema_evolution`.
  - Constructors: `new_merge`, `new_delete`, `new_update`. `inputs()` exposes
    write_plan + touched_files_plan + deletion_vector_plan. `fmt_for_explain` renders
    command, condition, assignment count, or MERGE clause counts.
- **`MergeCardinalityCheckNode`** — extension node over the full-join output that
  detects 1:N cardinality violations using `target_row_id_col` (stable per-target-row id
  added by `MonotonicIdNode`) + `target_present_col` + `source_present_col`.
- **`expand_merge(info: MergeInfo, path_column, row_index_column) -> MergeExpansion`**:
  - Renames source columns with a stable `__sail_src_*` prefix to avoid duplicate
    unqualified names after the full outer join.
  - Rewrites every ON condition, join-key pair, residual/target-only predicate, matched /
    not-matched-by-source / not-matched-by-target clause, generated-column expr, and
    Delta check-constraint expr through the rename maps.
  - **Insert-only fast append**: when only `NOT MATCHED BY TARGET` clauses exist *and* no
    clause references target columns, builds a `LeftAnti` join (insert rows) + `LeftSemi`
    join (noop rows, for metrics) union instead of the full outer join; touched plan is
    empty → physical `Operation::Append`.
  - **Default expansion**: full outer join of augmented target/source (presence columns
    `__sail_merge_target_row_present`, `__sail_merge_source_row_present`), optional
    `MergeCardinalityCheckNode`, `active_expr = target_present OR insert_expr` filter,
    merge projection, generated-column projection, and a **source-metric branch**
    (`count(*)` aggregated from the source plan, aliased `MERGE_SOURCE_METRIC_COLUMN`)
    unioned into the write plan so targeted rewrite can't lose source-row counts.
  - `build_rewrite_predicates` computes the touched-file filter: any matched clause or
    not-matched-by-source clause that actually rewrites rows; `touched_plan` =
    `join -> filter(rewrite_filter) -> aggregate(distinct path) -> project path`.
  - `deletion_vector_plan` = `join -> filter(delete_expr) -> project(path, row_index)`.
- **`expand_update(info: UpdateInfo, path_column) -> UpdateExpansion`**:
  - `write_plan` = target scan projected through
    `CASE WHEN condition THEN assignment ELSE current END` per assigned column, with the
    file-path column preserved.
  - `touched_files_plan` = `scan -> filter(condition) -> project(path)`.
- Constants: `SOURCE_PRESENT_COLUMN`, `TARGET_PRESENT_COLUMN`, `TARGET_ROW_ID_COLUMN`.

## 3. Resolver layer (`crates/sail-plan`)

### 3.1 `src/resolver/command/call.rs` (new, 383 lines) — CALL resolution

`resolve_command_call_procedure(name, arguments, state)`:
1. Enforces `<catalog>.system.<procedure>` fully-qualified shape and the `system` namespace.
2. Dispatches on the procedure name (case-insensitive):
   - `rollback_to_snapshot` → `resolve_table_and_snapshot_id` → `(table, i64)`.
   - `set_current_snapshot` → `resolve_table_and_snapshot_target` → exactly one of
     `snapshot_id` (positional/named) or `ref` (named only); both or neither → error.
   - `expire_snapshots` → `resolve_table_and_expire_args` → optional `older_than`
     (timestamp) + `retain_last` (i32).
   - anything else → `unsupported system procedure`.
3. Resolves the target table via `CatalogManager::get_table_or_view`; must be a
   **table** (not a view) with **Iceberg** format and a location.
4. Builds a `LakehouseExecutionContext` with `LakehouseOperation::Maintenance`, wraps
   table properties in `OptionLayer::TablePropertyList`, and constructs the
   `CallProcedureNode` extension.

Argument helpers:
- `resolve_named_arg(arguments, name, position, state)` — by-name (case-insensitive)
  else by position among *unnamed* args; evaluates the expr with `LiteralEvaluator`
  (must be constant).
- `resolve_optional_named_arg` — same, returns `None` when absent.
- Scalar coercions: `scalar_to_table_name` (Utf8/LargeUtf8/Utf8View),
  `scalar_to_snapshot_id` (all integer widths), `scalar_to_i32`, and
  `scalar_to_timestamp_ms` (matches the `TimestampSecond/Millisecond/Microsecond/
  Nanosecond` variants directly — per the `time_travel.rs` idiom — plus RFC3339/naive
  string parsing via `parse_timestamp_ms`).

### 3.2 `src/resolver/command/load.rs` (new, 96 lines) — LOAD DATA resolution

`resolve_command_load_data(local, location, table, overwrite, partition, state)`:
- Rejects `local` and `partition` (`LOAD DATA LOCAL` / `PARTITION` unsupported in v1).
- Resolves the target through the catalog; must be a table with `iceberg` format and a
  location. Builds a `LakehouseExecutionContext` with `LakehouseOperation::Write`, wraps
  properties, constructs `LoadDataNode`.

### 3.3 `src/resolver/command/update.rs` (new, 228 lines) — UPDATE resolution

`resolve_command_update(table, table_alias, assignments, condition, state)`:
1. `get_table_info_for_update` → location/format/columns/properties; builds a
   `LakehouseExecutionContext` (`Read`, then `.for_operation(Write)`); schema from
   catalog columns, or inferred from the datasource for DELTA when columns are empty.
2. Registers field ids and resolves the **target scan plan** via
   `resolve_update_table_plan` (a `spec::ReadNamedTable` query plan resolved through
   `resolve_query_plan`, then `rename_logical_plan` with real field names to undo the
   opaque-id aliasing).
3. Condition + each assignment are resolved against the renamed schema, then
   `expression_before_rename`'d back to real names. Assignment values are **cast to the
   target column's Arrow type** (e.g. `SET score = 100.0` on a DOUBLE column produces a
   Float64 column, not Decimal).
4. Builds `UpdateInfo` and calls `TableFormatRegistry::get(format)?.create_updater(...)`.

### 3.4 `src/resolver/command/mod.rs` (+39) — dispatches the new commands.

### 3.5 `src/resolver/command/catalog/table.rs` (+50)

Adds catalog-level `alter_table` path changes and the `ShowTblProperties` / describe
routing so Iceberg-REST-managed tables mutate through the catalog provider.

### 3.6 `src/resolver/query/read.rs` (+106) — Iceberg metadata tables

`try_resolve_iceberg_metadata_table(name, state)`:
- Splits the last name segment and, if `IcebergMetadataTableType::from_name(segment)`
  matches (`snapshots` / `refs`, case-insensitive), resolves the *base* table normally and
  re-targets the read with `SourceInfo.metadata_table = Some(metadata_type)` so
  `IcebergTableFormat::create_source` builds the metadata provider instead of the data scan.
- Otherwise the normal read path proceeds (`metadata_table: None`).

### 5.1 `src/table_format.rs` (+725) — the `TableFormat` impl

**`create_source`** — new metadata-table branch:
```rust
if info.metadata_table.is_some() {
```

**`build_iceberg_metadata_source(ctx, info)`** (line ~1183):
- Validates lakehouse storage access (`validate_iceberg_read_lakehouse_context`; rejects

- Parses the table URL, honors an optional `metadata_location` option for

**`alter_table`** — `reject_catalog_managed_iceberg_alter(lakehouse_table, &operation)`
now takes the operation and **allows `RenameTable`** (purely catalog-level). Dispatches:
- `SetTableProperties` → `alter_table_properties`
- `AddColumns` → `alter_table_add_columns`
- `DropColumns { names, if_exists }` → `alter_table_drop_columns`
- `AlterColumnComment` / `AlterColumnNullability` / `AlterColumnPosition` → per-column ops
- `RenameTable` → `Ok(())` (no storage mutation)

**`create_deleter(info: DeleteInfo)`** — builds a `RowLevelWriteNode::new_delete` over an
`EmptyRelation` + the DELETE condition (Iceberg DELETE is fully planned by the physical
planner, which re-scans the table itself).

**`create_updater(info: UpdateInfo)`** — calls `crate::logical::update::expand_update_node`.

**`create_merger(info: MergeInfo)`** — calls `expand_merge(info, MERGE_FILE_COLUMN, None)`
and wraps the expansion in a `RowLevelWriteNode::new_merge`.

**`plan_iceberg_write`** — now supports:
- `SinkMode::OverwriteIf { condition }` → `PhysicalSinkMode::OverwriteIf` and
  `SinkMode::OverwritePartitions` → `PhysicalSinkMode::OverwritePartitions` (previously
  `not_impl_err`).
- **Predicate validation**: for `OverwriteIf`, `extract_partition_predicate_from_expr` on
  the condition; every predicate column must be a partition column
  (`INSERT ... REPLACE WHERE` restriction).
- Serializes the partition predicate into `IcebergWriteOptions.overwrite_predicate`
  (JSON `Vec<(String, String)>`).
- The early `not_impl_err` for `OverwriteIf`/`OverwritePartitions` is removed.

**`retry_metadata_commit`** — extracted from `alter_table_properties` and generalized
into `pub(crate) async fn retry_metadata_commit<F>(object_store, store_ctx, table_url,
initial_latest_meta, check_post_write, mutate: F)` where `F: Fn(&mut TableMetadata) -> Result<()>`.
Both the pre-write version check and the post-write conflict check now use
`get_metadata_file_timestamp` + `is_stale_metadata_file` to ignore *stale* sibling
metadata files (a prior crashed attempt), retrying only on *real* concurrent writers.

**`alter_table_add_columns` / `alter_table_drop_columns`** — filesystem-path
implementations that load the latest metadata, build a new schema (new schema id =
max+1, fresh field ids from `last_column_id`), apply the change, and commit a new
metadata version through `retry_metadata_commit` with
`TableRequirement::CurrentSchemaIdMatch` + `LastAssignedFieldIdMatch` guards.

**`alter_table_column_comment/nullability/position`** — filesystem implementations for the
column-level ops (update the matching `NestedField` and commit a new schema version).

## 13. Port checklist — dependency order for re-implementing on feat/0.7

Re-apply bottom-up so each layer compiles:

1. **Spec/parser** (`sail-common` spec nodes, `sail-sql-parser` keywords+AST, gold data).
2. **Analyzer** (`sail-sql-analyzer/statement.rs`, `parser.rs`).
3. **Common surface** (`sail-common-datafusion`: `UpdateInfo`/`UpdateAssignment`,
   `MergeCapableSource`, `SourceInfo.metadata_table`, `TableFormat` methods,
   `IcebergMetadataTableType`, `ActivityTracker`).
4. **Logical plans** (`sail-logical-plan`: `call_procedure.rs`, `load_data.rs`, `merge.rs`).
5. **Resolvers** (`sail-plan`: `call.rs`, `load.rs`, `update.rs`, `catalog/table.rs`,
   `query/read.rs` metadata tables).
6. **Catalog commands + providers** (`sail-catalog/command.rs`, Iceberg-REST provider,
   memory rename, glue/hms/onelake stubs).
7. **Iceberg physical layer** (`table_format.rs` create_deleter/updater/merger/alter,
   `logical/update.rs`, `physical/` planners, `physical_plan/planner/*`, commit/action
   schema, execs, GC, metadata tables, scan-by-data-files file column).
8. **Distributed execution** (worker pool accounting, task assigner, spawn retry,
   readiness gate, k8s/local manager delete, codec + proto, session self-heal, activity
   tracker, server keepalive, config keys).
9. **Docker/K8s/build.sh**, then Python tests.

> Files that had *no* overlap with feat/0.7's own changes (pure additions) can be copied
> near-verbatim; files with overlap (commit_exec.rs, table_format.rs, action_schema.rs,
> statement.rs, task_assigner/core.rs, session handler, docker files, parser AST) need
> manual merge. See §0's per-commit overlap analysis for the risky ones.
